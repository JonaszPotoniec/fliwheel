# TWA / iQuiz (Bundle 11002)

**Status:** 🟡 Menus render, packs load (2026-11-10) | **Engine:** iQuiz Engine

## 2026-11-10 fixes
- `miscTBD:2` is `realloc(ptr, size)` (string reserve at `0x1803b5f8`). It
  returned 0, so every guest string append kept only its last piece and all
  packs opened a bare `trivia.txt`. It now shares Vortex's realloc, so each
  pack opens `UserTrivia/Packs/<pack>/trivia.txt`.
- A reopened staged file starts at offset 0 (packs after the first read 0 bytes).
- The colour uniform (OpenGLES:148, location 4) is kept per material. Only the
  slider material sets one (all zeros, from BSS `0x18078534`); as a global
  register it blanked every later draw, so the name-entry wheel, text and icons
  never appeared.

- The null page reads as zeros (`zero_null_page_reads`). After a few
  minutes idle the game quits and saves; with no name entered yet it runs
  `strcpy(buf, name.c_str())` on a null pointer (fault at `0x18001c18`, caller
  `0x1801169c`). Low memory is mapped on the iPod, so the read is harmless there.

- Texture name 0 is a real texture for the TWA titles. Question screens are
  drawn in software and uploaded into GL's default texture (bind 0, then
  OpenGLES:105 every frame); treating 0 as "unbound" dropped those uploads and
  the round showed stale pixels as bars.

- Vertex-colour alpha is applied for the TWA titles (`with_vertex_alpha` in
  `live_gl.rs`). Music Quiz 2 draws "Time's Up!" every frame at alpha 0, and
  question transitions fade through a full-screen overlay; ignoring alpha left
  the banner always visible and made each fade a black screen.

- Sound effects play. The game decodes `sounds/iquizSfx` (31 WAVs after a
  count + length table) itself and hands each source a raw PCM pointer with
  `Audio:7(handle, pcm)`, after `Audio:8` byte length, `Audio:10` rate,
  `Audio:11` channels and `Audio:12` bits. `bind_raw_pcm_audio_source`
  wraps those bytes in a WAV under `.fliwheel-saves/pcm-sfx/` and `Audio:2`
  plays it (wheel tick, select). This is the default for every title except
  Vortex, Hold'em and the file-bound WAV titles; the Sims and SAT Prep games
  set the format after `Audio:7`, so binding waits for the last setter or
  `Audio:2`, and an all-zero buffer (Tetris loads it later) stays unbound.

Still open: Movie/Music Trivia appear twice in the pack list. Music
(`bg.m4a`, `mq.m4a`) never plays: the stream calls `Audio:40/43/47-60` are
stubs.

## Issue

TWA's rendering pipeline has three distinct problems:

### 1. Pack directory discovery — ❌ CORPUS PATH MISMATCH
The async directory request is traced through its callback, but the decrypted
bundle does not contain the directory the executable requests:
`UserTrivia/Packs`. The current bundle has a bundled sample at
`UserTrivia/Samples/sample1` plus the separate `UserTrivia/BuiltIn` content.
No permanent alias or synthetic pack list is installed by the emulator.

### 2. Pack content loading — ❌ BLOCKED
After the directory callback, the game calls
`AsyncFileIO:0` with `path="data"` — a generated index/cache file that
doesn't exist in the bundle. The executable expects this file to contain
metadata about available packs. Without recovering that format, the game
never opens the actual `.ipd`/`.tga` files from a user-pack directory.

The "data" file is likely built by the game at runtime on a real iPod
from scanning pack directories. Our `AsyncFileIO:0` handler resolves
the path to `.fliwheel-saves/data` which creates an empty file. Existing
bundles from the predecessor HLE may still contain `.clicky-saves`; the
runtime reads that legacy directory but writes new saves under the fliwheel
name.

### 3. Texture association — ❌ BLOCKED
The game uploads a 2×2 A8 placeholder texture (handle 0xDE1) then
binds material handle 0x28 for drawing 149×75 pack icons. The upload
and draw use completely different GL texture names — no upload matches
the draw's UV span.

Root cause: TWA's ordinal-45 (`glPrepareTexture`) creates empty
texture descriptors (all zeros at call time), then the game fills them
in later. Our ordinal-45 handler exits early because the descriptor
hasn't been populated yet. Even with the fix to not early-return,
the descriptor is still zeros — the game writes the texture name
AFTER ordinal-45 returns but BEFORE ordinal-99 uploads pixels.

The real pack icon textures would be loaded through the pack loading
pipeline (blocked by issue #2), so fixing the texture association
alone won't help until packs load.
